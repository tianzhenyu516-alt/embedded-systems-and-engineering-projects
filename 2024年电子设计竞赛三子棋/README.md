# 2024 年电子设计竞赛｜视觉三子棋系统

这是一个把视觉识别、棋局决策和实体落子连接起来的三子棋工程。程序要判断棋盘状态，还要把下一步棋转换为机械机构可执行的坐标和动作。仓库保留 STM32 下位机工程与视觉相关代码，可以从感知、通信、执行三个环节理解完整的嵌入式项目。

## 项目看点

- **从像素到棋格**：视觉侧提供棋盘和棋子信息，下位机通过串口接收并组织棋盘状态。
- **从棋格到运动**：`My_main.c` 中有坐标与电机步数的换算，以及步进电机的加速、匀速、减速控制。
- **分任务组织流程**：按键和状态变量管理不同任务，便于追踪识别、判断与移动的先后关系。
- **保留完整入口**：STM32Cube/HAL 工程配置与应用代码一并收录，方便定位引脚、串口和定时器。

## 阅读路线

1. 看 [`src/1-6ALL/MDK-ARM/Individual_Code/My_main.c`](src/1-6ALL/MDK-ARM/Individual_Code/My_main.c) 的棋子坐标、运动逻辑与任务状态。
2. 看 [`src/1-6ALL/Core/Src/main.c`](src/1-6ALL/Core/Src/main.c) 的外设初始化与程序入口。
3. 对照 `src/SHIJUE/` 中的视觉程序，追踪视觉结果如何传给控制板。

## 展示价值

这个项目最能体现的是把抽象规则落到实体设备上的能力：棋局中的一格并不天然对应电机的一段距离，必须经过视觉坐标、棋盘标定、运动换算和动作时序的层层转换。阅读代码时，也可以看到为比赛任务做出的具体工程选择及其适用范围。

## 复现提示

使用对应 STM32 板卡、步进驱动和视觉模块，并根据实际棋盘重新标定坐标、零点、串口和电机方向。源码中的延时脉冲方案服务于落子过程，换到持续实时控制任务时需要重新评估。工程内的 ST/Arm 底层文件保留原声明，详见[来源说明](../THIRD_PARTY.md)。
