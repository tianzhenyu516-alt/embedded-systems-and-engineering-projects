# 2026 年数学建模 C 题｜建模、求解与结果核验

这里按题目问题组织 Python 建模程序，覆盖数据筛选、变量构建、优化求解、结果验证和图表生成。项目的价值不仅在于给出数值答案，还在于把假设、计算和核验拆成可追踪的步骤，方便复查每一问的输入、输出与约束。

**负责人说明：** Skylar 担任队长，组织建模任务拆解、脚本求解与结果核验。下面的目录说明对应公开的计算文件，具体分工与结论以项目记录为准。

## 解题结构

- `src/数据分析/`：筛选与整理附件，形成后续模型使用的数据。
- `src/第一问/`：线性规划建模、数据工具与结果校验。
- `src/第二问/`：参数扫描、边界检查与候选结果整理。
- `src/第三问/`：问题三的计算流程与多日场景代码。
- `src/第四问/`：问题四的主程序、单次运行和审计脚本。
- [`src/generate_all_figures.py`](src/generate_all_figures.py)：集中生成展示图表。

## 展示价值

分问目录、扫描脚本与核验脚本使计算过程具有可追踪性。阅读者可以看到一个建模方案怎样从数据整理进入约束设计，再通过边界检查与图表表达接受复核。这比只给出结果表更能展示问题拆解和计算验证能力。

## 阅读与运行

建议先看 `src/数据分析/` 如何生成模型输入，再依次阅读每一问的主脚本及 `verify_*.py` / `*_audit.py`。`附件/` 和 `src/` 中的表格、CSV、序列化数据与脚本存在路径依赖，运行时应保持目录结构，并按脚本导入项安装 Python 依赖。换一份数据时应重新执行准备、求解和核验。

仓库展示可复查的计算过程与必要输入，不包含报名信息、个人材料和论文草稿。
